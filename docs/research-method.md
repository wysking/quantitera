# 经济机制研究如何保留 V6 能力

QuantItera 保存可追溯的研究过程：原信息是什么、何时能知道、原来预期什么、可能经什么渠道影响资产，又有哪些竞争解释。程序核对事实和条件，研究者负责提出与评价经济机制。

## 从信息到机制

1. **原始信息**：event 保留来源引用、摘要、指标、单位、观察期间、发布时间、捕获/可获知时间与修订。引用本身不是引擎已联网核实的证明。
2. **事前预期**：expectation 要在事件前已被工作空间获知，并与事件目标、单位、期限和期间匹配。事后补填不构成原预期，冲突来源不静默平均，单个分析师观点不称市场意外。
3. **机制假设**：config/research.json 写 hypothesis、horizon、alternative_explanations、invalidation、next_observation。不同期限证据不自动合并。
4. **支持与反证**：mechanism_evidence 的 supporting、counter、context 分开。重复事实不增加置信，来源异议和竞争解释保留在机制卡片。
5. **可检验判断**：价格条件和经济机制分开归档。达到阈值只支持对应市场条件，不证明机制；缺独立渠道识别时因果状态仍待识别。
6. **复盘与新研究**：评价原判断哪些部分仍有效、哪些被反驳、错误与缺口、下一假设，下一轮 discuss 和模型取得同样反馈。

## 可运行示例

```sh
python -m examples.research_demo --workspace ../new-mechanism-demo
```

全部是合成数据：先登记融资利率预期 3.00，后登记事件 2.75。原实现计算差值 -0.25 个百分点。融资成本降低是支持线索，投资订单走弱是反证，最终需求走弱是竞争解释。机制卡片同时保留材料，causal_status 仍为 hypothesis_not_identified。

两条预先保存的代理收益判断均为 >=1%，分别遇到 -2% 和 +2% 的完整窗口，结果为 refuted 和 supported。复杂机制先保持 awaiting_evaluation，随后示例研究者提交人工复盘，明确因果尚不确定。该复盘完成但不自动整体打分。

下一研究包包含反驳、错误、缺口与新假设；成长模型要求人工复核，参数与版本不变。完整输出在 exports/tutorial/ 和两份成绩中。可直接阅读 [示例研究报告](../examples/research/research_report.md)。

## 为什么能积累

判断和证据只追加，旧观点通过 supersedes 保留替代关系。review_id 联系原判断，错误和新假设不随新报告覆盖；检索、discuss 与模型都读取这些反馈。积累的是研究记忆和证据，不等于自动训练参数、校准概率或已经证明投资能力改善。

候选机制可以通过私人已有 factor_candidates 能力进入原流程；未配置时不会建立第二套因子库。候选、研究资格、因果识别和生产模型集成分别处理。
