## 本轮修复

- 批量请求原先人为递增微秒，最终导出使用批次起始时间，导致后续已成功记录暂时不可见。现统一使用该次研究截止时间。
- 复盘原先按带时区的文本排序。现按实际时刻排序，UTC 人工完成不会被更早的 UTC+8 待评价覆盖。
- 同一截止时间先补缺口再完成时，完成结果具有终态优先级，与队列关闭行为一致。
- discuss 增加 global_research，避免新资产入口漏读通用经验。

## 运行与自动化

```sh
python -m pip install -e '.[test]'
python -m pytest -q
python -m pytest tests/test_cli_acceptance.py -vv --basetemp runtime/acceptance
```

第二条运行完整回归；第三条保留合成工作空间供检查。`--as-of` 仅用于可复现验收，日常刷新使用默认当前时间。

公开 CI 在 Ubuntu / Python 3.12 上运行全部测试，并构建 wheel，在独立环境使用 `-I` 初始化工作空间、提交并重新克隆，然后运行工作空间 Actions 所用的 refresh 和 git add 步骤。这同时检查安装包包含隐藏的工作流文件，以及空目录在 Git 克隆后仍可运行。

工作空间模板沿用 GitHub Actions，每周一至周六 05:15 UTC、周一至周五 09:15 UTC 定时检查，也响应 inbox、inputs、config 更新。任务串行执行，仅在私有仓库启用；安装版本固定为 v0.1.2。已有工作空间更新安装版本即可，无需重新初始化或覆盖事件。

公开 CI 和模板的本地步骤验证不等于实际私人部署已经完成。本阶段没有创建或改接私人工作空间，也没有实测新私人仓库的定时触发和推送权限；这些须在下一阶段接入后核对。

## V6 能力与当前边界

来源核对与行为测试确认：证据保留原始来源、时间、观察期间、单位和修订；事前预期比较保留原算法；机制卡片保留支持/反证、竞争解释、证伪条件和下一观察，只将原固定机制定义改成工作空间输入。它支持 ChatGPT 寻找并继续检验经济机制，程序不会凭价格涨跌证明因果。

当前仍需私人数据入口提供行情与经济证据；没有内置自动数据抓取服务或无人值守的大模型研究。复杂经济/政策评价通过 ChatGPT 的 record_review 完成。下一轮自动取得反馈依赖从 CHATGPT_WORKFLOW.md 或 discuss 进入研究；无法保证绕过入口的对话也会使用这些记录。

价格验证目前支持登记标的的 close_return_pct / close_level 与 gte/lte；日历为 2021—2026。未知标的、其他指标和后续年份需要按实际需求补充。个人模型计算、组合优化、策略调权和账户/交易适配没有在此阶段开发。

## 下一阶段私人接入所需工作

1. 选定独立私人工作空间，备份现有事件；保留原个人资产模型、组合、策略及交易账本。
2. 将现有数据入口输出映射到 inputs/market.json，将需验证的模型判断写成 inbox 请求，明确标的、口径、review_at 与 review_spec。
3. 将原研究机制和可追溯证据放入私人 config / record_evidence；ChatGPT 入口读取资产及 all 反馈。无需把模型或数据搬入公开引擎。
4. 对实际私人仓库检查 Actions 写权限、版本固定与自动回执，在副本中跑通后再切换入口。既有私人 P1 PR 是否合并或改为适配应单独处理。
